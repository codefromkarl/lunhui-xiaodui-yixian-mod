## 发现、修正与保留的失败证据

1. **内伤时序效果缺省基数。** 首轮Mono为25组通过／1组失败，唯一失败是`basis=0`的兼容警告。按游戏原生`BuffAmountBasis.Flat=10`补齐声明，增加原生枚举检查；后续真实Mono诊断清洁通过。这是已复现的内容兼容缺陷，没有观察到它造成进程崩溃。
2. **测试夹具重复初始化。** 新增边界用例最初在已有牌桌上再次调用初始化，触发原生字典重名异常；游戏未退出。按原生方法的“该slot尚无牌桌”前提，测试重建前仅移除私有夹具的对应牌桌；原生边界复测通过，没有改写游戏初始化逻辑。
3. **运行时重新追加冗余说明。** 实际截图发现旧增量在精简JSON之后又拼接原文和适配长文。统一详情入口只返回实际效果；离线测试与真实预制体逐卡预览直接核对最终文字，来源资料仍保存在数据中。
4. **异常退出证据不足。** 旧启动器在超时分支不复制日志，也不记录正在执行的用例。现在自测执行前落盘`activeCase`，启动器区分断言失败（1）、超时（3）、进程提前退出（4）；等待结束时记录`watchdog.json`，从启动到结束的路径均留存日志。提前退出仅代表观察到进程消失，具体原因仍由日志判断；失败路径用单元测试模拟，不通过强杀游戏测试。
