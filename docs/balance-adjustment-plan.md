# 首轮最小调整与配对验证方案

## 原因与范围

前次证据不支持直接整体加强五行或降低灵剑费用。五行的试验主题曾把金丹／元婴池换成持续、防御牌；高阶三包也可能没有永久印记。剑宗种子 91002 的灵气线在第一回合打出万法归灵剑后，斗气由 96 变为 0，属于原有“耗尽斗气”效果，不能作为错误扣费修复。

首版只改玩家可用的构筑建议和提示，保留原卡费用、伤害、回气、仙命、突破成本与存档格式。既有选择不自动改写。五行建议接入已有的“推荐构筑”面板；测试输入必须与实际推荐方法一致，不能只优化测试配置。

## 预定候选（先定方案，再观察结果）

- 五行金火：以基础印记包 `roots` 作为三包之一，再放本境界金火兑现包；不默认追加第四包。
- 五行水木：同样保留 `roots`；金丹保留有攻击与土印的 `cycle` 过渡，元婴用 `forest_sea` 替换偏持续的 `cycle_seed`，化神用 `roots + evergreen + forest_sea`。
- 五行土灵／混元：保留带土印及攻击牌的 `cycle`；金丹为 `cycle + cycle_seed + roots`，元婴为 `cycle + great_cycle + cycle_seed`，化神为 `cycle + origin + great_cycle`。不假设高阶必须全五行永久激活。
- 剑宗灵气：保留灵剑四／五阶核心，第三包优先用 `cloud4` 代替 `cloud3`，引入云剑·灵海并移出额外收费续牌的巨鹏灵剑。化神当前组装费预计从 325 增至 360 点，必须披露，不能称为同预算增强。
- 面板显示当前选包的永久印记覆盖／缺失；灵气说明明确万法会耗尽斗气，应考虑续航与终结时机。保持自由选包与原生确认保存流程。

## 同种子对照与验收

1. 先保存当前源文件、DLL、内容和配置哈希，重新运行修改前主矩阵。不能只拿上次汇总充当新基线。
2. 四个种子仍为 `91001–91004`；相同属性请求、赠包索引、两种出牌策略、静止耐久沙袋、四回合、每回合 24 次上限。**出牌策略不随调整改变**。
3. 修改后主矩阵采用生产推荐方法及匹配的优先级配置；新增五行推荐不改变 `gifts/newest` 对照。包次序继续按 index 统一。
4. 主矩阵每侧 672 个组合；低属性请求每侧 672 个组合。前次第四包补印记的实验不混入新的三包建议。
5. 按门派／境界／主题／策略／种子／赠包／仙命逐行配对，比较实际包、组装支出、四回合生命削减、出牌数、缺气回合、永久激活和预算截断。不同卡池只保证种子相同，不保证手牌相同。
6. 接受方向：五行已标记的成长回落显著收窄，目标消除超过 25% 的相邻境界回落；主题保留至少一个目标元素的印记入口。剑宗灵气主策略的缺气回合至少减半，平均生命削减不低于原来的 75%。若未达标，明确记录未解决项，不为通过阈值临时改策略或扩大无关增益。
7. 未调整的剑宗云剑／剑意、七星、只赠包和最新包组合，轨迹应完全一致。命令错误、队列泄漏、越界、倒地／提前终局、出牌截断均不得新增。

四种子仍是探索性证据。通过表示该构筑干预值得进入完整游玩，不产生胜率或数值已平衡的结论。若候选失败，只允许另行记录原因和新候选后复测；不得覆盖失败证据。

## 交付

调整说明、生产推荐与界面提示、必要的构筑／隔离测试、逐行配对脚本和结果。原始数据写入本机忽略目录 `logs/balance-adjustment/`；结果另写 `docs/balance-adjustment-results.md`。正常游戏安装不热替换，实机对照仅使用独立副本。

价格对账将灵气化神组装费校正为 360 点（原方案 325，增加 35），先前说明的 365／40 属计算错误；未改变卡包价格。首轮规则配对有效，但新增控件测试因测试父对象未激活、原生 Awake 未挂接按钮而失败。修正夹具生命周期后完整复跑；保留失败报告。五行仍有筑基输出回落，化神水木存在印记覆盖与输出的权衡，本轮不继续按四个种子追逐阈值改数值。
