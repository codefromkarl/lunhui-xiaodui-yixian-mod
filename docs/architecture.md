# 一个底座，门派各自拥有规则

## 公共层负责玩家如何拿到并打出牌

- `SectRegistry`读取一个权威牌表，登记门派、牌、包与归属；无效输入在替换现有注册表前拒绝。
- 不全局伪造`TryGetLineageRank(BL08)`：门派只获得卡牌引擎能力，不等于已持有BL08。纯门派的启用卡包入口独立接管，原生与混合血统走原生路径。
- `CardTableBridge`是唯一原生目录与抽牌补丁入口。`BuildCatalog`只构造目录；`InjectCatalog`在游戏Mono中提交，并在第二次写入失败时恢复。
- `SectProgression`按卡包所属门派的境界判断资格；只用最高门派阶数打开原生卡牌引擎入口，不用于跨门派解锁。
- 入宗赠本门派两个炼气包；剑宗筑基二选一及后续购包保持原样。三派均开放完整五境界，每派48张牌、12个四张包、4个独立仙命。
- 进度的正式购买和直接赠与入口均在新增第二门派前拒绝，不扣奖励点、不推进修订号；商店条件隐藏其他门派。原生血统搭配不受限制。
- 共用出牌经济：首回合3张、主动摸牌1行动力／0斗气、出牌0行动力／仅按单卡灵气费用扣斗气（1灵气＝4斗气），无额外基础费，减费可降至0、手牌最多10张、最多8个启用包。

## 门派层负责本张牌如何结算

- `Sects/Sword`保留既有48张牌与四仙命结算，除用户确认的费用修正外，不重写其他数值。
- `Sects/FiveElements`拥有主动灵印激活、上一元素、锋锐／加攻／水势与五灵阵。只有灵印或明确仙命写入永久激活掩码；已激活、同属性或金→水→木→火→土→金相生可满足单卡元素条件，普通牌不自动激活。中性卡清上一元素但不清激活。五个独立单层元素图标显示激活位，不把掩码当层数。持续牌本场消费，合计最多2张。详见[五行原作适配](five-elements.md)。
- `Sects/SevenStars`拥有跨宿主回合保留的成功卡牌数、虚拟八格星位、常驻星力、逐次卦象和同源使用次数。默认3／6为星位，第9张回1格；原生卡推进格位。后招从本场同源第二次使用触发。卦象对每个独立随机结果取最优，消耗一层但不推进该次RNG。随机仍由`CodeBattlePlan.Random`生成。详见[七星原作适配](seven-stars.md)。
- 两派各48原牌保留`sourceId`、原名、真实境界、归档1级原文、卡面费用证据和逐牌适配；不再使用原创牌换名冒充原作。资料快照及图文版差见`data/sources/original-correction/SOURCES.json`。
- `OriginalCardBridge`在新玩家牌桌初始化之前只清该角色的五行／七星战斗状态和待摸请求，避免原生开场发牌早于BattleStart而读到上场持续牌标记；不改剑宗、其他玩家或其他包的状态。BattleStart前从真实启用卡包注入五行种数。抽池和支付前准入统一调用`SectCardRules.CanPlay`，已消费持续牌不会重抽，手里残留牌拒绝时不支付或移牌。
- `OriginalHealthRules`将临时生命上限、直接生命减少和可挡的非攻击伤害分别排队，在权威Mod钩子提交后消费；最大生命通过公共maximum规则和临时状态实现，不伪造体质。调上限再治疗保留先后顺序；直接减生命绕盾，非攻击伤害先扣盾，均不叠攻击属性。七星护体最多32个独立单层原生实例，避免原生一次移除整组护体；生命周期差异在单卡适配中明示。这条Mono桥的正式命令与表现仍待实机验收。

## 状态、身份与旧局

发布ID保持`yixian.sect`；剑宗状态键`sword.<actor>.<key>`保持，五行／七星使用`five`／`star`前缀。新派额外摸牌请求使用`cards.<actor>.drawPending`；公共桥在同一权威事务中消费请求，旧剑宗摸牌键仍兼容。

门派状态写入`CodeModStatePlan`，不使用静态战斗计数或本地随机数。预览只生成计划，不修改输入快照。战斗开始清本门派状态；玩家之间按actor隔离。保存／恢复沿用原生状态映射。

v0.6.0起，内容身份统一为`yixian.sect.lineage.<school>`、`yixian.sect.card.<key>`、`yixian.sect.pack.<pack-key>`与`yixian.sect.fate.<school>.<key>`。原生牌桌构造器返回的本包新对象由`CardTableBridge.BuildCatalog`显式投影`AbilityId`、`UnlockAbilityId`及`CardIds`；不修改原生或其他包对象，不替换原生BL08身份。卡包key、货架序号及目录次序保持（剑宗40～49、51、52；五行60／61、80～89；七星70／71、90～99）；50不复用。按用户决定，不保留旧ID别名、精确映射或存档恢复补丁；新版不兼容旧ID存档，需开新局。不屏蔽命名警告。详情和当前候选状态见[身份迁移](identity-migration.md)。不能同时加载新旧同发布ID的包。

仙命图标的用户授权修正使用对应原作资源；v0.6.0仅随内容身份迁移其`icon.<内容ID>`键，不改变资源文件：剑韵修炼16、云之道69、剑阵守护57、云海连绵14；保盾状态共用57。原图在`mod/yixian.sect/icons/fates/`，登记源是`data/sword/manifest.json`。兼容检查对这五处路径使用明确的新期望，其余旧资源映射保持不变。

兼容夹具在`tests/fixtures/sword-v032/`；`check_contracts.py`将历史夹具仅用于规则回归：按卡牌名称／key关联费用，并排除已变更的身份字段后逐项比对规则和图像路径；卡牌说明与摘要、以及内容字段flavour由独立呈现检查覆盖；新身份及引用单独严格检查。不改写历史夹具，不维护旧→新ID表。新增学校数据位于`data/*/school.json`，共享编译器生成原生内容、公式详情和卡包列表；剑宗数据源保持原始完整定义。

## 验证边界

原生 HUD 的 `IsCardTableCommand` 只识别 BL08 前缀；门派桥额外按注册表识别本包卡牌，使首回合手牌归入卡牌页，并从能力页及自定义能力栏排除。不能通过改回旧 ID 解决。回归覆盖三派起手、真实 HUD 预制体分栏，以及费用预告／HUD 费用徽标／实际扣费的一致性；飞牙剑按原卡1灵气，消耗4斗气。

`CardTableHudLayout`为本包门派牌桌的总览说明预留页签上方文字行，并把原生抽牌／卡包／命运按钮定位在视口右侧。手牌宽度为按钮留位后交回原生扇形排布；尺寸变化后重新计算，离开本包牌桌恢复原生布局。图形回归覆盖三派／四种实际相机视口、3张和10张手牌，核对按钮、手牌和说明的完整边界、文字溢出、相交及非门派布局恢复。

`CardIllustration`只改变本包手牌中的图片呈现。原作完整PNG和证据不变；运行时从统一卡面右上插画窗创建等比裁剪Sprite，排除原卡竖排卡名、费用及下部旧正文，填满手牌上部。当前费用、名称、类型和详细实际效果沿用原生呈现路径。裁剪Sprite复用源纹理、缓存后使用，并随图标库清理释放；池化控件转为其他牌时恢复原矩形和显示属性。

CoreCLR验证原生内容投影、规划、公式、随机状态和补丁目标存在性；不执行游戏捆绑MonoMod detour或readonly目录写入。正式命令、实际伤害、抽牌事务、原生存档映射与预制体渲染由`-yixian-selftest`在游戏Mono中验证。截图不代替实际鼠标命中检查；联机另行验收。

## 单卡费用契约（费用修正）

`rules.cost`表示单卡灵气费用；剑宗48张牌必须逐张显式填写，包括0费。独立费用证据在`data/sources/original-correction/original-costs.json`，以原卡左上角标为准，并保存所查卡面的RGBA像素哈希；正文快照不含角标，不能据此判为0费。不得用伤害段数、境界或回气量推导费用。斗气费用＝`rules.cost × 4`，不收通用基础费。百鸟减4斗气，最低0；御空的有盾免气、追风的连云免气可以完全免除。万法的耗尽剩余斗气是卡牌效果支付，不是通用出牌费；御灵心法只按实际消耗／恢复量加盾，免费牌不产生虚假的支付护盾。

内容声明、单卡／卡包说明、费用预告、可用性检查及实际扣费必须一致；原生BL08仍走原生费用。`scripts/card_costs.py`维护生成端的换算，`SectCardRules.PrintedCost`维护运行时换算；回归用独立原卡证据和明确0／4／8／12的例子验证，不能只从同一份`rules.cost`推导预期值。飞牙4、巨鹏8、巨鲲12、三峰0为固定对照。兼容夹具不改写，比较时只按独立卡面证据归一已授权的费用，其余规则逐项保持。

## 独立仙命与扩展编译

两新派的四个仙命由school.json的fates定义，统一编译为独立Learned被动、40点货架与各自境界阶；规则由门派自有FateRules执行，不占手牌。SectRegistry.Fates仅保存元数据供详情与列表使用，不作为战斗计数器。新派规则描述分别由five_content和star_content按实际参数生成。两派96张原牌与8项仙命使用缓存原图，仅做WebP→PNG格式转换；Mod状态图标由代码绘制。`prepare_original_assets.py`统一准备资产；`build_prototype_art.py`跳过有sourceId的原牌和有来源图的仙命，不覆盖它们。不修改剑宗已纠正的原作图标。

## 解锁不等于启用，推荐不等于提交
纯门派的`SectProgression.Refresh`保留现有合法启用顺序，只补齐原生`min(3,owned)`最低数量；不因发现新购包而全部加入。现有存档中的已启用包不移除。BL08和混合路径仍交回原生。

`SwordBuilds`只按境界和已购包生成三条路线的建议，不写权威状态、不购买卡包。`SwordBuildPanel`只修改原生面板的`selected`待选集合，沿用原生确认/取消及`SetPacks`命令；不另建本地保存或提交通道。UI上下文使用弱引用，仅保存境界信息，不保存战斗状态。推荐入口只对纯剑宗的普通卡包管理显示；原生、混合、其他门派及命运一抽均不替换。

池子统计按当前待选包的真实卡牌规则计算，云剑比例对应等概率有放回的抽牌池，回气/摸牌是含条件效果的卡牌数，不是保证触发次数。手牌详情复用原生ActionCardViewModel的实际费用预告，不另算一套费用。测试准备手牌时显式走原生SetPacks启用已购目标包，不依赖购买副作用。


## 卡牌说明只讲实际效果

`data/presentation.json`维护144张卡的用途摘要、门派公共规则、卡包定位和仙命／状态说明；`five_content.py`与`star_content.py`按实际规则生成公式、条件和限制，`presentation_copy.py`只在生成时整理剑宗既有文案。原作文本、来源、费用证据和适配记录保留在原数据字段，不复制到日常牌面。

单卡详情按“效果／条件／必要限制／实际斗气费用”组织；条件免气、取整例外、次数、持续时间、伤害与直接失去生命的区别不能省略。公共的换算、行动力、星位、后招、剑意和五行激活规则放在门派介绍及状态说明中，卡包保留用途、获取方式和四张完整单卡详情。

摘要使用显式`summary`字段，概括主要效果与关键条件，不截取详情第一行。原生卡牌摘要与能力单行介绍共用`SectDescriptions.CardSummary`。卡名、身份、境界、卡包成员／次序、货架价格、规则参数、费用与结算实现不随呈现优化改变。

`test_presentation_copy.py`检查全部牌面的费用、摘要覆盖、来源／规则保留及特殊限制；C#描述测试验证原生摘要路由、门派规则入口和代表性条件效果。历史夹具不改写，玩法回归不忽略数值或结算字段。


## 崩溃排查与测试证据

内伤的原生时序效果显式使用`basis: 10`（`BuffAmountBasis.Flat`）；省略会触发运行时兼容警告，词汇／JSON加载检查本身不能发现这一枚举缺省问题。身份测试同时检查时序效果基数的有效原生枚举。

显式自测在每项执行前先写`status=running`与`activeCase`，结束后更新同一条记录。启动器遇到进程提前退出返回4、超时返回3、断言失败返回1；所有终止路径复制Player／Mod日志。进程提前退出不直接等同原生崩溃，需结合最后用例、日志及系统记录判断。

全量Mono套件包含156次连续出牌的生命／重施／护体边界检查，以及带历史状态的真实牌桌初始化前缀检查。原生`InitializeCardTablesOrThrow`要求指定slot尚无牌桌；测试重建前只移除该隔离夹具的牌桌，不能重复初始化后将字典重名异常误报为游戏崩溃。

实际预制体逐卡点击后的文字必须等于“卡名＋生成的精简效果”，不能在运行时再次追加原文和适配说明；来源字段保留在数据中。自测使用私有内存RunAuthority，不能绑定用户RunManager或调用存档主机。
