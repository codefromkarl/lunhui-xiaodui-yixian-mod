# 构筑最小调整与同种子对照结果

日期：2026-10-20。结论是**局部改善，保留取舍，尚未解决全部成长问题**。本轮修改构筑建议、印记覆盖提示与相关验证工具，未改原卡费用、伤害、回气、仙命、卡包价格或突破规则。

这是第一轮的历史记录。后续水木／筑基优化见 [第二轮结果](balance-refinement-results.md)。当前默认输入改为 `balance-refined-*`；本页 `balance-adjusted-*` 保留当时的固定卡池，重放时关闭生产建议绑定，避免把新生产建议冒充旧方案。当时完整矩阵与生产方法一致性的回执仍保存在原证据目录。

## 做了哪些调整

- 五行接入已有的推荐构筑面板。金火／水木在三包内保留基础印记包；土灵／混元保留土灵印与基础攻击包，减少金丹阶段持续牌挤占攻击的情况。不默认强制追加第四包，也不自动改写已有选择。
- 当前选包与推荐显示永久印记覆盖、缺失元素及相生／仙命仍可启动的提示。合法无印记池仍可自由保存，并未获得免费的开局激活。
- 剑宗灵气线在元婴起优先放入云剑·灵海所在包；化神保留两包灵剑核心，用它替换旧的金丹云剑包，减少额外付费续牌并改善回气。
- 明示万法归灵剑会耗尽斗气；水木高阶说明明示稳定启动与短战输出之间的取舍。套用仍只改变待选包，需原生确认才生效。

方案在改动前记录于 [调整方案](balance-adjustment-plan.md)。本轮没有调整出牌策略来配合候选，也没有按四个种子继续追逐阈值修改卡牌数值。

## 对照条件与有效性

修改前、修改后各跑主矩阵和低属性请求矩阵：每套 672 个配置组合，共 **2,688 个组合、10,752 个回合、1,344 个逐行配对**。

固定种子 `91001–91004`、赠包索引、两种策略、属性请求、仙命条件、四回合及每回合 24 张预算。双方开局耐久 10,000、敌方跳过行动，仍使用真实购买／选包／摸牌／出牌／回合命令，不补气或行动力。每行完整配对门派、境界、主题、策略、种子、赠包及仙命。

两套各有 568 组卡包未变的对照，合计 **1,136 组的实际手牌与逐回合轨迹完全一致**，0 意外变化。四套均无命令错误、倒地、提前终局或出牌截断；存档隔离与正常退出回执通过。修改后每个主题从生产推荐方法取包，并检查配置与生产方法一致。

两侧卡牌内容哈希相同：`d557398bd2eaffbcbc6c7692401d6a070d589047acfad040188000929a419899`。这次测的是**构筑干预**，不是相同卡池下的卡牌数值增强。不同池只保证共同种子，不保证相同手牌。四种子包含等价池重复，不是数千个独立随机样本。

## 主要收益与代价

以下为主矩阵、优先建立机制／回气策略、不买仙命、四回合平均敌方生命削减。它包含回合间观察量，不能当成胜率。

| 对象 | 原构筑 → 新构筑 | 当前三包组装费 | 解释 |
|---|---:|---:|---|
| 五行混元金丹 | 103.75 → 202.5 | 87.5 → 65 | 比筑基 171.75 高约 17.9%，原来约 −39.6% 的邻阶回落消除 |
| 五行水木元婴 | 144.75 → 416.25 | 192.5 → 105 | 新金丹为 202.5；原金丹→元婴约 −31.1% 的回落消除 |
| 五行金火化神 | 295.5 → 378.25 | 325 → 255 | 印记入口与高阶兑现保留在三包内 |
| 五行水木化神 | 520.75 → 348 | 320 → 255 | **约 −33.2%**，以印记入口换取启动机会；不是全面升级 |
| 剑宗灵气化神 | 1,229.75 → 1,228.5 | 325 → 360 | 输出约 −0.1%；缺气回合从 **7/16 降至 3/16** |

组装费是独立夹具购买最终所选包的支出；含两种赠包选择时显示均值。它不代表真实战役沿途总支出。

低属性请求也复现关键方向：混元金丹仍为 `103.75→202.5`，水木元婴 `139→399`；剑宗灵气化神输出 `1,194.5→1,198.5`，缺气同样 `7/16→3/16`。水木化神仍下降，`487.75→330.25`，因此没有把它表述为低属性下也全面增强。

### 成本不能只看最后三包

剑宗化神当前组装费增加 **35 点**，元婴的当前配置平均组装费从 `195→280`，增加 85 点。如果沿整条主题逐阶买包，新增的灵海包要花 **105 点**：历史包费从 `325/365→430/470`（对应两种赠包），不是整条路线只贵 35 点。面板未自动购包，资金不足仍只推荐已购包的过渡选择。

五行最终三包的组装费虽降低，但沿途早已购买、后来退出启用池的包仍归角色所有。三条五行主题的历史包费均与旧路径相同；不能据当前组装费下降宣称战役省了同样多的钱。

## 印记改善的边界

原来三个五行化神主题的四种子均无永久激活。新推荐均包含目标元素的印记入口：金火为金／火、水木为水／木、土灵为土。

在主策略、无仙命化神组中，金火与水木四个种子都有实际永久激活；土灵只有两个种子抽到了土灵印并激活，另两个四回合仍未抽到。**补入口不等于保抽到**，本轮不暗改抽牌概率或赠送开局印记。

全合法池中的无印记组合数也未减少；改变的是推荐与可见提示。自由使用原三高阶包仍被允许，尤其水木化神的旧池在本探针中输出更高。

## 仍未解决的项目

- 相邻境界下降超过 25% 的标记由每套 **10 个降为 6 个**。剩余均为五行筑基的土灵／混元、水木、盲选最新包，两种策略各一条；它们本轮没有换包，不能声称已修复。
- 水木化神在两种策略下都有明显输出代价；有仙命的主矩阵也出现约 25.6% 回落。它应作为偏印记启动的选择进入实玩，不能取代所有输出构筑。
- 金火元婴、混元化神的同阶输出也有下降，详见逐组配对。没有用更高的金丹／元婴平均值掩盖这些代价。
- 剑宗仍有 3/16 个缺气回合，新包路径更贵。万法的耗尽效果可能在正常敌人被终结时无需再续航；高耐久沙袋会放大后续资源压力。新版属于长战周转建议，不说明原效果扣费错误，也不说明短战一定更好。
- 静止敌人不能评价治疗、防御、受击仙命的补偿收益，更不能决定真实奖励是否足以支持新增购买。完整三派游玩仍待执行。

预先约定的“混元金丹／水木元婴回落收窄”和“剑宗缺气至少减半且保留 75% 输出”均通过；“消除全部成长标记”未通过。配对脚本分别记录检验完整性与这些验收结果，不以整体 `passed` 掩盖剩余问题。

## 工程与界面检查

构建零警告／零错误，48 项 Python 测试、6,153 项 C# 检查、186 项仙命检查与内容契约检查通过。新测试涵盖五境界的归属／购买限制、印记覆盖提示、生产推荐与测试配置一致性，以及原生确认后的正式换包不消耗点数、不替换当前手牌。

真实 prefab 检查验证三条五行建议的暂存、一次原生确认及切到仙命页时隐藏推荐层。无图形模式没有验证屏幕排版、物理鼠标与字体渲染；未把这一部分描述成视觉验收。探索时控件夹具未激活父对象、导致原生 Awake 未挂接按钮的失败报告已保留，修正后复跑通过。

正常游戏安装没有热替换本轮 DLL；源码包已编译，验证只在独立副本完成。

## 复跑与数据

在仓库根目录配置好 `.env.local`，正常退出目标测试副本后运行：

```sh
source .env.local
# 修改前的固定选包；当前 DLL 仍可按该输入重放原构筑
python scripts/run_yixian_runtime_tests.py --balance --balance-config data/balance-scenarios.json --game "$HOME/Games/ReincarnationSquadBalanceSteam" --direct-game --headless --quit-after-tests --timeout 600
# 第一轮修改后的固定选包重放
python scripts/run_yixian_runtime_tests.py --balance --balance-config data/balance-adjusted-scenarios.json --game "$HOME/Games/ReincarnationSquadBalanceSteam" --direct-game --headless --quit-after-tests --timeout 600
python scripts/compare_balance.py --before <before>/balance-results.json --after <after>/balance-results.json --out logs/balance-adjustment/replay-comparison.json
```

低属性请求分别使用 `data/balance-low-attribute-scenarios.json` 与 `data/balance-adjusted-low-scenarios.json`。目录审计可用 `scripts/balance_audit.py --config <配置文件>`；默认读取第二轮推荐。

原始四套报告、完整种子轨迹、退出回执和 DLL 位于 `logs/balance-adjustment/{before,after}/{main,low}/` 及其父目录；配对结果为 `main-comparison.json`、`low-comparison.json`，哈希与最终界面补测见 `evidence-manifest.json`。以上本机证据目录被 Git 忽略，公开方案、输入与脚本保存在源码中。
