# 三派成长、选包与资源循环验证方案

## 目标与边界

验证 v0.7.0 三派在炼气、筑基、金丹、元婴、化神的成长成本、卡包选择和资源循环。先收集证据，不在本轮直接调整玩法数值。工作区已有的手牌 HUD 修复保留；报告注明测试的实际工作区版本。

分三层取得证据；另用独立 C# 规划快照检查零费回气／抽牌组件，快照不证明自然战斗能够完成循环：

1. **目录与经济审计**：读取权威内容，枚举每境界合法启用包组合；对账突破、赠包、购包与仙命成本，计算起手费用压力和关键卡的抽取概率。
2. **真实 Mono 战斗矩阵**：使用现有私有内存 RunAuthority，经过正式购买、启用、抽牌、出牌与结束回合命令，测量真实支付和收益；不使用指定手牌、不额外补气、不在回合中补行动力。
3. **完整游玩验收**：后续人工在真实奖励收入、敌人和事件中验证通关体验。前两层不能代替这一层，战斗探针不产生胜率或完整通关结论。

## 试验矩阵

- 三派 × 五境界；共同固定种子，记录每个种子、配置与出牌轨迹。夹具按包 index 统一顺序，相同集合获得相同随机映射；不同卡池仍不意味着相同手牌。
- 五类包配置：只保留赠包、盲选最新三包、三条主题路线。剑宗复用当前三条推荐；五行比较金火、水木、混元；七星比较星位、卦雷、后招。
- 两种出牌策略：手牌顺序优先；先建立未有的机制、在缺气时回气的简单策略。两者均只读取当前手牌和公开状态，不预知未来 RNG，不作为最优策略。
- 主矩阵默认 4 个共同种子、4 个宿主回合，每回合最多 24 次出牌。另检查两种筑基赠包选择。
- 基准不买仙命，便于分离卡包本体效果；另以代表性配置加入本境界可购仙命做敏感性检查。
- 开发命令分别请求属性值 10 与 1；宿主仍保留原生基础／境界下限，实际值不一定等于请求值，必须以记录为准；这不是自然角色成长轨迹。保留原生境界气池及其余被动，记录实际属性、气池、开局斗气与行动力。卡包必须真实购买且合法启用，支出逐项记录；充足测试点数仅用于组装配置，不代表战役收入足够。
- 双方仅在夹具组装时通过本场最大生命状态设置耐久 10,000；敌方只在开局设置跳过行动 99 次，隔离原生 AI。之后不回填生命／斗气／行动力。原生回合、状态、消耗和摸牌仍真实结算；记录实际回合数和提前终局，禁止把截断样本与完整四回合直接排名。耐久和静止敌人的设置不能用于验证生存、治疗与受击仙命强度。

- 补充选包对照：五行化神三条主题各加一个已拥有的基础印记包；保留原三包，卡池从 12 张变 16 张，购包支出不变，同时观察启动收益和稀释代价。

## 记录指标

| 维度 | 指标 |
|---|---|
| 成长 | 逐阶与累计突破成本、赠包价值、主题配置增量支出、仙命支出、解锁与实际启用是否脱节 |
| 选包 | 合法组合数、费用分布、起手无零费牌概率、关键启动卡缺失、每包稀释效果、最低启用包数限制 |
| 资源 | 每回合出牌／主动摸牌／保留到手的额外摸牌、报价费用／牌效净斗气变化（并非总恢复量）、气池触顶、无气卡手、手牌耗尽、行动力耗尽 |
| 机制 | 五行永久激活种数与持续牌消费；七星星位／星力／卦象；剑宗连云／剑意／减费 |
| 输出 | 按实际命令累计的敌方生命与护盾变化、自身护盾、治疗；只比较相同条件，不等同完整战斗强度 |
| 有界性 | 达到每回合出牌预算、状态或队列异常、原生命令被拒绝、角色意外倒地 |

## 预先约定的筛选标准

- **确定缺陷**：非法获取／支付、合法命令异常拒绝、队列泄漏、负资源、状态越界；必须有种子和最后命令。
- **成长风险**：升级但不购包时卡池不变；购包支出相对突破成本跃升；主题在某境界前缺少启动组件。记录事实，不凭测试点数假定真实战役经济。
- **选包风险**：合法组合没有零费牌，或没有主题启动／恢复组件；指出最小复现组合和起手概率，不直接判为不能玩。
- **循环风险**：至少两个共同种子出现首回合无合法可支付牌；或相同预算下两策略都频繁无气／无手牌；或到达出牌上限。触及上限表示截断和需复测，不直接宣称无限循环。
- **成长拐点**：同一路线相邻境界出牌数或输出下降超过 25% 时列为调查项；小样本和沙袋条件不产生强弱定论。
- 每条发现标明：静态事实、真实命令复现、策略敏感，或待完整游玩验证。

## 执行与交付

先运行 `python3 scripts/balance_audit.py`，再运行 `python3 scripts/run_yixian_runtime_tests.py --balance --timeout 600`。后者须先正常退出游戏，并使用本地配置完成安装和代码许可；不强退、不热重载。

机器可读数据和逐回合轨迹写入 `logs/balance/` 与实机报告目录；可公开的方案、复跑入口和结论写入 `docs/`。保留失败样本，报告同时说明样本量、规则版本、预算和尚未覆盖的战役环节。

## Mac 资源探针复跑

在已登录 Steam 的原 Wine 前缀中运行。独立副本仅安装 `yixian.sect`，`Mods/enabled.json` 的 `packages` 为 `["yixian.sect"]`，沿用用户已授予的代码许可；在副本根目录写入 `steam_appid.txt`，内容为 `5241190`。这用于保留开发启动参数，仍须通过 Steam 初始化。

```sh
source .env.local
python scripts/balance_audit.py
dotnet run --project scripts/yixian-tests -c Release -- --balance-plans
python scripts/run_yixian_runtime_tests.py --balance --game "$HOME/Games/ReincarnationSquadBalanceSteam" --direct-game --headless --quit-after-tests --timeout 600
# 低请求属性与加基础包对照分别添加：
# --balance-config data/balance-low-attribute-scenarios.json
# --balance-config data/balance-support-scenarios.json
python scripts/summarize_balance.py logs/yixian-runtime-tests/<run>/balance-results.json
```

先编译、安装探针 DLL；不要向运行中的副本写 DLL。`--headless` 只验证规则和命令，不验证界面／Shader。Unity 无图形模式的 Shader 警告与图形设备初始化失败应区分。新 Wine 前缀没有 Steam 会话，本轮采用现有前缀，临时 authority 不绑定正常存档。代码许可不是绕过 Steam 身份验证。

若本体提示上次启动未到主菜单而暂不加载 Mod，先让安全模式进入主菜单并正常退出，再启动测试。自测退出器等待原生主菜单完成启动保护，再写退出回执，不删除或跳过启动保护。
