# 牧逸风 · 完整像素外观 Mod 0.2.0

独立包 `appearance.muyifeng`。为《轮回小队 Demo》的本机玩家重绘完整脸形、眉眼、鼻口、发髻前发、后发、白蓝衣袍和靴子；同步原生队伍头像及战斗 HUD 头像。不依赖 `yixian.sect`，不新增血统、卡牌、数值或角色存档字段。

## 与 0.1 的实质变化

0.1 只替换头发和上衣，留下原生娃娃脸，并将设计图中的区域缩小为部件。0.2 完全移除了这条导入路径：运行时不读取设计图、不裁切、不缩小图片。生产素材是 `art/muyifeng-pixels.json` 中可逐格审阅的调色板网格，一个字符严格对应一个纹理像素。

`build_pixel_parts.py` 直接在最终像素坐标绘制轮廓和色块，不读取任何位图。眉毛、眼白、瞳孔、鼻口有独立像素簇；完整头部替换原生头形，并隐藏原生眼睛、胡须和前发，防止叠回旧面部。头身统一按 56 PPU 制作，衣袍、腿部和靴子也一起重画。

| 部件 | 原尺寸纹理 |
| --- | --- |
| 完整头部（含眉眼、前发和发髻） | 32×40 |
| 后发 | 24×40 |
| 上衣躯干 | 28×28 |
| 左右袖（各） | 16×20 |
| 左右下摆／裤腿（各） | 12×23 |
| 左右靴子（各） | 10×14 |

设计方向来自之前认可的 ImageGen 图。新版通过内置 ImageGen 生成分部件参考，再将生产像素独立编写成可编辑网格。`art/muyifeng-atlas.png` 和 `art/muyifeng-parts-reference-v2.png` 仅为设计参考，完整提示词及制作方式在 `art/provenance.json`；两张图都不是运行时素材。

## 文件与构建

- `src/`：独立 C# 工程、显示补丁和显式开启的游戏内验证。
- `mod/appearance.muyifeng/`：可安装包。
- `scripts/build_pixel_parts.py`：生产像素源的权威作者文件。
- `appearance.json`：启用开关及像素源文件路径。
- `output/final-v2/`：本机最终截图、动作录像、机器报告及安装包，不进入 Git。

在仓库根目录配置合法游戏安装的 `GAME_MANAGED` 后：

```sh
python3 appearance-muyifeng/scripts/build_pixel_parts.py
dotnet build appearance-muyifeng/src/MuyifengAppearance.csproj -c Release -p:GameManaged="$GAME_MANAGED"
```

游戏程序集不随源码分发。生成图和生产像素 JSON 均在项目内，实际运行只需要安装包中的 DLL、配置和生产像素源。

## 安装与恢复

将包目录放到游戏 `Mods/appearance.muyifeng`，在 Mod 管理启用并允许作者“你”的代码，然后正常重启游戏。已运行的进程不会热加载新版。本机身份来自原生 `SessionSnapshot.LocalPlayerSlot`；其他玩家、敌人及召唤物保留原样。

```sh
python3 appearance-muyifeng/scripts/install.py --game "/实际游戏目录" --apply
```

安装器保留其他包、备份原包及启用／许可文件，回执位于 `output/installation-*`。默认拒绝更新运行中已有的包。显式 `--stage-running-update` 使用整包备份和目录切换，为下次启动准备新版；不在原位置改写已加载 DLL，也不强制关闭游戏。停用本包并重启可恢复原生外观。读档是否接受包更新仍由本体的 Mod 一致性检查决定。

## 实际尺寸验证和动作录像

```sh
python3 appearance-muyifeng/scripts/verify.py --game "$HOME/Games/ReincarnationSquadAppearance"
```

仅 `-muyifeng-verify -muyifeng-quit` 会启动测试。普通游戏不创建测试对象、不采样测试动画、不导出 PNG 或录像帧。Mac 测试使用独立游戏副本、现有 Wine/Steam 会话及包装器 DXMT，有图形渲染；测试局不绑定用户战役存档。

取得随游戏发布的 `PF_PlayerCombatant`，使用真实 `BattleCombatantView`、SPUM 骨架／动画片段和 `NodePartyPortrait`。本机身份通过原生单机会话验证。原生面部、衣服、武器的恢复和对象池复用也纳入检查。

画面上排直接调用本体 `NormalizePerceivedHeight(camera)`，测得原生／新版角色在 1600×900 的捕获视图中均约 **107 像素高**，对应 1280×720 窗口约 **85–86 像素**。下排明确标注 **2.4 倍细节检查**，不用于替代正常尺寸验收。初始标准尺寸固定后，各动作保持同一比例。

动作录像以 24 fps 连续捕获 336 帧，共 14 秒，覆盖待机、移动、近战攻击、受击、倒地、真实左右镜像及恢复。每帧检查自定义部件仍在、原生眼睛／胡须没有重新出现。头像检查包含本机专属绑定、对象复用、缓存刷新及像素输出非空。

最终机器报告还记录完整脸部替换、九个部件、原尺寸纹理、发色、队友／召唤物隔离、武器保持、真实骨骼姿态变化、镜像方向反转和恢复，以及测试前后存档清单不变。必须取得本轮新报告、通过状态和正常退出回执，才算验证成功。

这些是原生组件在独立游戏副本中的隔离验证截图和游戏内动作视频，并非用户存档内一场完整战斗的桌面操作录屏，也不声称战役通关或多人联机已经验收。

## 接入与兼容

使用 Harmony 接入内部显示函数，游戏更新后可能需要适配。保留原生骨架、关节、动画、武器挂点和排序。后发作为头部的子渲染器跟随动画，延用原生材质、头部颜色和排序层；受击、高亮和倒地颜色保留。原生面部的隐藏及全部替换都限定于已绑定的本机玩家，并在角色复用／停用时恢复。
